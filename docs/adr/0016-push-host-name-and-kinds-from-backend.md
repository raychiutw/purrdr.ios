# 推播主機的電腦名稱與圖示存在後台，通知種類由後台提供

#431（spec #422）原本決定：後台**永遠不知道主機名稱**。後台送出的通知只有 `workspace · Tab` 標題與 `loc-key` 內文，主機名稱由 app 的 Notification Service Extension 依配對雜湊，查 App Group 裡的本機對應表補進副標題。通知種類（需要你、完成、可能卡住、仍在等你、主機服務）則在 app 的 `PushKind` 與後台的 `push.ts` 各寫死一份。

使用者 2026-11-28 決定改掉這兩件事（grill：通知種類與通知主機）。本 ADR 取代 #431 的「後台不知道主機名稱」。

## 決策

- **後台存推播主機的電腦名稱與主機圖示**：
  - **名稱**：app 裡這台主機的顯示名稱，也就是使用者取的名字。
  - **圖示**：使用者選的主機圖示，以系統圖示代號加顏色傳送，不傳圖片。
  - 開通知時由 app 送出；在 app 改名稱或圖示時同步更新。
  - **不存**主機位址、IP、埠號、使用者名稱、host key 或任何連線資訊。
- **通知的副標題由後台直接放主機名稱**。Notification Service Extension 的本機對應表留著，只給後台還沒有名稱的舊配對當備援。
- **通知種類清單由後台提供**：
  - 每一項帶：代號、英文與繁中的名稱和說明、新配對預設開不開、適用的連線方式、需要的主機服務最低版本、順序、是否停用。
  - app 照清單畫開關；後台驗證配對的種類時也以這份清單為準。
  - 加一種新的通知種類，只要後台加一筆，不必 app 改版。種類本身由主機外掛或主機服務送出，所以加種類仍可能要改主機端。
- **配對收哪幾種以後台為準**：app 經 API 讀寫，本機的紀錄只在升級前當備援。

## 為什麼

- 換手機、或主機沒存在這支手機上時，通知照樣有名稱；「通知主機」清單也能由後台直接提供，各裝置一致。
- 加通知種類原本要 app、後台兩邊一起改版，現在只改後台。
- 代價是後台多知道使用者電腦的顯示名稱與圖示。這些是使用者自己取的標籤，不是連線資訊，風險可以接受。

## 影響

- 隱私權政策網頁（`docs/site/purrdr/`）與 App Store 的隱私標示要寫明：後台會存開了通知的主機的顯示名稱與圖示。
- 主機同步（Plus）本來就會把名稱與圖示傳到後台，這次把同樣的資料擴大到「有開通知的主機」，不需要 Plus。
- GLOSSARY「推播配對」「通知種類」照此更新。
