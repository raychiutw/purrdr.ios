# 主機在線狀態：主機服務向後台送心跳，後台只存最新狀態

使用者 2026-11-28 決定 0.55.0 加入「主機離線」與「主機已恢復」兩種通知（grill Q19、Q23～Q26）。後台要判斷主機是否在線，必須收主機的定期回報；這表示後台開始知道「某台主機什麼時候開著」。這份 ADR 記錄這個隱私取捨，以及限制後台知道多少。

## 決策

- **只有主機服務送心跳，而且只在有人要收時才送**：至少一組推播配對開了「主機離線」或「主機已恢復」，那台主機的主機服務才開始回報。都沒開就不送，也不產生資料。SSH 主機沒有常駐程序，不支援這兩種通知，開關停用並說明要安裝主機服務。
- **頻率**：每 5 分鐘一次心跳；連續 15 分鐘沒收到，判定離線。後台以每 5 分鐘一次的排程（Cloudflare Cron Trigger）檢查。
- **睡眠**：電腦進入睡眠前，主機服務先回報「睡眠中」（macOS 以系統的睡眠通知；Windows／Linux 有對應的系統通知就照做）。後台不把睡眠中判定為離線，醒來時也不送「已恢復」。沒能先回報的情況（直接斷電、網路斷掉）照樣判定離線。
- **後台只存最新狀態，不存歷史**：每台主機只存「最後一次心跳時間」與「目前狀態」（在線、睡眠、離線），沒有時間序列，所以後台無法重建使用者的作息。心跳內容只有配對識別與狀態，不帶 IP、位址或任何連線資訊。Cloudflare 的 request 本身帶 IP，但後台不記錄。
- **通知**：「主機離線」「主機已恢復」是兩種通知種類，預設不開。照 ADR-0016 的通知種類清單提供，需要的主機服務最低版本寫在清單裡。

## 為什麼

- 使用者想在主機掛掉時（例如 Agent 跑到一半電腦斷線）收到通知。
- 只在有人開通知時才送、只存最新狀態，讓後台多知道的資料降到最少。
- 先回報睡眠，可以避開筆電闔上就誤報這個最常見的情況。

## 影響

- 隱私權政策網頁與 App Store 的隱私標示，要寫明：開啟這兩種通知時，後台會知道那台主機目前是否在線。
- purrdr.host：主機服務新增心跳與睡眠回報，在有配對開了這兩種通知時啟用。
- purrdr.server：新增心跳 API、狀態欄位與排程。
